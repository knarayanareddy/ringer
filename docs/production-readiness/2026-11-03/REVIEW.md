## Findings ledger

- **RNG-1 — Medium, confirmed static. AccessHold's `exists` predicate does not actually evaluate existence semantics.** The contract supports `"exists"` ([contracts/src/index.ts:22-27](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/contracts/src/index.ts#L22-L27)). In the sampled policy engine, missing features become **`"feature_unknown"`** ([policy-engine/src/index.ts:73-76](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/policy-engine/src/index.ts#L73-L76)), while the `exists` branch returns **`status: expected ? "satisfied" : "violated"`** without checking presence ([policy-engine/src/index.ts:124-131](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/policy-engine/src/index.ts#L124-L131)). Impact: existence checks can be wrong or unknowable at an approval boundary. Recommended correction: evaluate presence explicitly and add failing negative tests.

- **RNG-2 — Medium, confirmed static. AccessHold distinguishes evidence verification levels in the contract but the sampled policy evaluator never uses them.** `AccessEvidence` records **`verification_level: VerificationLevel`** with values such as `"provider_confirmed"` and `"unverified"` ([contracts/src/index.ts:9-12](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/contracts/src/index.ts#L9-L12), [contracts/src/index.ts:55-65](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/contracts/src/index.ts#L55-L65)). The sampled evaluator checks source type, provenance, and staleness, then calls `evaluatePredicate` ([policy-engine/src/index.ts:178-196](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/policy-engine/src/index.ts#L178-L196)); no `verification_level` gate appears in the inspected range. Impact: `unverified` evidence can satisfy hard constraints. Recommended correction: set minimum verification thresholds and fail closed when only unverified evidence exists.

- **RNG-3 — Low, unverified risk. Repo-level quality claims should not be translated into product-runtime assurances.** The README warns that **"Static UI/design validation and source-level fixture tests do not prove platform behavior"** ([README.md:61](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/README.md#L61-L61)), and `specs/ui/package.json` says the shared UI pack is **"not an application runtime"** ([specs/ui/package.json:5-10](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/specs/ui/package.json#L5-L10)). Snapshot metadata shows no sampled recent runs (`evidence/ringer/snapshot.json:449-450`). Impact: aggregate repo summaries can overstate maturity. Recommended correction: keep claims workspace-specific and tied to observed outputs.

## Five-discipline assessment

- **Correctness / code review:** AccessHold shows meaningful domain modeling: semantic validators catch duplicate IDs, interval errors, missing linked assets, and provenance mismatches ([contracts/src/index.ts:123-198](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/contracts/src/index.ts#L123-L198)). However, RNG-1 and RNG-2 sit directly in the policy path, so correctness is not yet strong enough for any real approval or booking boundary.
- **Automation / testing:** Sampled manifests show build/lint/type/test scripts per workspace, including `test:security` in AccessHold and static/browser/audit validation in `specs/ui` ([accesshold/package.json:10-18](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/package.json#L10-L18), [specs/ui/package.json:6-10](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/specs/ui/package.json#L6-L10)). But I did not inspect test bodies, and no sampled CI run history proves these gates were recently executed at the pinned SHA.
- **DevOps / operations:** The repo intentionally avoids a shared runtime and uses multiple toolchains: Node 22 for TypeScript foundations, Java 17 for Kotlin harnesses, Python 3.12 plus `uv` for Python foundations ([README.md:27-37](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/README.md#L27-L37)). That is a legitimate structure for a collection, but it raises release, environment, and recovery complexity. No sampled source proves a deployment topology, artifact promotion path, restore drill, or operator runbook.
- **OWASP / security:** The strongest sampled security shape is in AccessHold and CurioLab. AccessHold records provenance and evidence hashes and validates fixture/live mixing ([contracts/src/index.ts:61-65](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/contracts/src/index.ts#L61-L65), [contracts/src/index.ts:166-183](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/accesshold/packages/contracts/src/index.ts#L166-L183)). CurioLab excludes raw images: **"frame buffers and images never enter this API"** ([perception/src/index.ts:123](https://github.com/knarayanareddy/ringer/blob/371babc6e7d3d6d30f1f5ca99b4515c254b58636/projects/curiolab/packages/perception/src/index.ts#L123-L123)). Authn/authz, secret handling, injection surfaces, dependency hygiene, and live provider boundaries are mostly outside inspected ranges.
- **UI/UX / accessibility:** Shared UI validation exists, but the sampled evidence itself says it is static only and not runtime proof. No sampled wireframe, browser run, keyboard path, focus order, screen-reader behavior, or Fire TV remote interaction was inspected. UI/accessibility should therefore be treated as largely unverified, not absent.
